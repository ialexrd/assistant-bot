# ИИ-ассистент химчистки

Бот на DeepSeek (можно переключить на Claude), который сам ведёт заявки по переписке с клиентами в Telegram и ВКонтакте.

**Как работает**
1. Незнакомый человек пишет вам → ИИ по первым сообщениям понимает, клиент ли это,
   и заносит в CRM заявку со статусом «новая». Вам приходит уведомление с кнопкой «Не клиент».
2. Вы как обычно договариваетесь и в конце пишете клиенту «Записал, спасибо!» →
   бот читает переписку, ИИ достаёт имя, телефон, адрес, дату, время, мебель и сумму,
   записывает заказ в CRM (статус «записан», копия в Google Таблицу) и присылает вам карточку
   с кнопками **Ок / Исправить / Отменить**. «Исправить» — пишете или говорите голосом, что поменять.
3. В личке с ботом можно давать поручения текстом или голосом: «Анна отказалась»,
   «перенеси рилс на пятницу в 15», «добавь фразу-триггер „ждём вас“».
4. Каждая новая заявка, записанный и исправленный заказ дублируются письмом на вашу Яндекс Почту.
5. Постоянные клиенты: когда визит прошёл (дата в прошлом) или заказ выполнен либо отменён, следующее сообщение
   клиента — новое обращение. ИИ снова проверяет, заказ ли это, и заводит новую заявку; старый заказ не меняется.
   «Записал» в таком диалоге создаёт новый заказ. Пока визит впереди, переписка относится к текущему заказу
   (например, перенос), и «Записал» обновляет его.
6. Утром: план дня из планера и незакрытые заявки с готовыми текстами. Вечером: сводка мастеру на завтра.

Фразы-триггеры по умолчанию: «записал», «записала», «записали», «записываю», «вы записаны».
Регистр, знаки и ё/е не важны, «Записал, спасибо!» и «записала вас на четверг» сработают.
«Могу записать вас?» не сработает. Список: `/phrases`, менять можно словами в чате с ботом.

## Что понадобится
1. **Сервер**: любой VPS с Ubuntu 22/24, 1 ГБ памяти. DeepSeek работает и из России.
2. **Ключ DeepSeek**: platform.deepseek.com → API keys, пополнить баланс (Top up).
3. **Токен бота**: @BotFather → /newbot. Затем там же: Bot Settings → **Secretary Mode** (раньше Business Mode) **→ Turn on**.
4. **Telegram Premium** на вашем аккаунте: без него Telegram для бизнеса недоступен.
5. **Ключ Firebase**: console.firebase.google.com → проект crm-orders → ⚙️ Настройки проекта →
   Сервисные аккаунты → «Создать закрытый ключ». Скачается JSON.
6. **ВКонтакте** (по желанию): в сообществе Управление → Сообщения → включить.
   Управление → Работа с API → Ключи доступа → создать с правами «Управление сообществом» и «Сообщения сообщества».
   Там же вкладка Long Poll API: включить, версия 5.199, типы событий «Входящее сообщение» и «Исходящее сообщение».
7. **Голосовые**: Яндекс SpeechKit (ключ и id каталога в console.yandex.cloud, роль `ai.speechkit-stt.user`)
   или OpenAI Whisper (`STT_PROVIDER=openai`). У DeepSeek и Claude нет распознавания речи.

8. **Яндекс Почта** (по желанию): в ящике Почта → Все настройки → Почтовые программы → разрешить
   доступ по IMAP/SMTP («С сервера imap.yandex.ru по протоколу IMAP» и «Пароли приложений»). Затем
   id.yandex.ru → Безопасность → Пароли приложений → создать для «Почта». Его вписать в `SMTP_PASSWORD`.

## Ассистент в ВКонтакте (если Telegram недоступен)
Впишите свой id ВК в `VK_OWNER_IDS` (напишите сообществу «/id», бот ответит числом). Тогда сообщения
сообществу с вашей страницы — поручения ассистенту, как в личке с Telegram-ботом: «запиши Наталью на завтра 11:30,
3000», голосом тоже, можно пересылать сообщения. «отмена» откатывает последнее изменение. Уведомления о новых
заявках и записях при `TELEGRAM=off` приходят туда же. Скриншоты переписки бот читает через Яндекс Vision OCR (тот же ключ Яндекса,
нужна роль `ai.vision.user`), слева сообщения клиента, справа ваши.

**Расписание картинкой**: напишите сообществу «расписание», «расписание на завтра», «расписание на неделю»
или «расписание 05.11» — бот пришлёт карточки заказов, как в мобильной CRM. Работает и в беседе (например,
с мастерами), куда добавлено сообщество: команду должен написать владелец. «отправь скрины мастеру на завтра»
(или «расписание мастеру …», можно голосом) отправляет картинку мастерам в личку от сообщества (их id в `VK_MASTER_IDS`; мастер должен хоть раз написать
сообществу).

## Установка на сервер
```bash
sudo apt update && sudo apt install -y python3-venv ffmpeg git fonts-dejavu-core
sudo git clone https://github.com/ialexrd/assistant-bot /opt/assistant-bot && cd /opt/assistant-bot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env          # вписать токены и ключи
nano firebase-key.json                     # вставить содержимое скачанного ключа Firebase
sudo cp deploy/assistant-bot.service /etc/systemd/system/
sudo systemctl enable --now assistant-bot
journalctl -u assistant-bot -f             # логи
```
Узнать свой id: написать боту `/id`, вписать в `OWNER_IDS` (и `MASTER_CHAT_ID` для мастера),
затем `sudo systemctl restart assistant-bot`. Нажмите у бота /start, мастер тоже.

## Подключить бота к Telegram
Telegram → Настройки → Telegram для бизнеса → Чат-боты → ввести @имя_бота.
В «Доступ к чатам» выберите **«Все, кроме…»** и исключите контакты (так бот не видит переписку с друзьями
и семьёй). Бот пришлёт «Бот подключён». Писать от вашего имени он не будет, ему нужно только чтение.

## Обновление
```bash
cd /opt/assistant-bot && sudo git pull && .venv/bin/pip install -r requirements.txt
sudo systemctl restart assistant-bot
```

## Как устроено
- `bot/core.py` — новые клиенты → заявка, фраза-триггер → заказ, карточка, исправление, отмена.
- `bot/llm.py` — запросы к ИИ с ответом в JSON (разбор переписки, «клиент ли это», тексты) и цикл агента.
- `bot/agent.py` — агент для лички с ботом: ИИ с инструментами CRM, планера, заметок, настроек.
- `bot/main.py` — Telegram (личка, Business-переписка, кнопки, расписание), `bot/vk.py` — ВКонтакте.
- `bot/dialogs.py` — переписка хранится на сервере в `data/dialogs.db` (SQLite), `data/settings.json` — фразы.
- Переписка учитывается с момента подключения бота: старые сообщения Telegram и ВК боту не отдают.

ИИ по умолчанию DeepSeek (`deepseek-chat`). Чтобы вернуться на Claude: `LLM_PROVIDER=anthropic`
и `ANTHROPIC_API_KEY` (нужен сервер вне РФ), модель `claude-opus-5-5`, у Claude включена запасная модель
на случай отказа.

## Статусы заявок в CRM
`new` новая, `thinking` думает, `booked` записан, `done` выполнен, `lost` отказ.
Старые заказы без статуса считаются записанными. Утром напоминаю про `new` и `thinking`.

## Проверка без ключей
`python -m tests.smoke` прогоняет логику на заглушках (без Telegram, Firebase и ИИ).
